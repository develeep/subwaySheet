# 정적 사이트 + 설문 함수 하나 (Cloudflare Pages), 월별 데이터는 레포에 커밋

화면은 Vite + React로 만든 정적 SPA이고, 서버 코드는 Cloudflare Pages Function 하나뿐이며 저장소는 D1이다. 이 함수는 추천 기록(결과 화면 노출)과 설문 응답 두 가지만 받는다. PRD는 "서버는 설문 저장 하나뿐"이라고 했지만, 설문 응답률(KR3)의 분모를 정확히 세고 한 추천에 응답 하나만 받으려면 추천 기록도 서버에 남겨야 한다. 칸 점수는 앱이 정적 데이터로 계산하므로(ADR 0001) 화면에는 서버가 필요 없다. 익명 설문은 스팸이 KR 측정을 흐리기 쉬워서, 클라이언트가 BaaS에 직접 쓰는 방식 대신 검증과 레이트 리밋을 걸 수 있는 함수 하나를 두었다.

월별 배치(TypeScript)는 GitHub Actions cron으로 매월 돌며(원천 데이터마다 갱신 주기가 월·분기·연으로 다르다, ADR 0003), 결과 데이터를 레포에 커밋해 배포를 일으킨다. 생성물을 커밋하는 이유는 달마다 데이터가 어떻게 바뀌었는지 git 이력으로 비교하기 위해서다.

## Considered Options

- Next.js 같은 풀스택 프레임워크: 서버 렌더링이 필요 없는 앱이라 과하다.
- Supabase에 클라이언트가 직접 insert: 익명 insert는 RLS만으로 스팸을 막기 어렵다.
