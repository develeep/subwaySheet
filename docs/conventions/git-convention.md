# Git Convention

## 브랜치

- `master`가 배포 브랜치입니다. master에 들어간 커밋은 Cloudflare Pages가 바로 배포합니다(#12).
- 작업은 master에서 짧은 브랜치를 따서 하고, PR로 master에 병합합니다. `develop`·`release` 브랜치는 두지 않습니다.
- master 직접 push는 하지 않습니다. 예외는 월별 배치 워크플로(#11)가 정제 데이터를 커밋하는 것 하나뿐입니다.

### 브랜치 이름

- 기능·일반 작업: `feature/{YYYYMM}-{작업명}`
- 배포된 것의 긴급 수정: `hotfix/{YYYYMMDD}-{작업명}`
- 여러 단어는 대시(`-`)로 잇습니다. 언더바(`_`)는 쓰지 않습니다.

예: `feature/202610-2호선-추천-모듈`, `hotfix/20261103-설문-제출-오류`

## 커밋 메시지

형식:

```
<타입>: <요약>

<선택: 본문>
```

- 타입: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`
- 요약은 한국어로, 무엇을 바꿨는지 한 줄로 적습니다.
- 본문에는 왜 바꿨는지와 같이 확인할 것을 적습니다.

예:

- `feat: 2호선 본선 추천 모듈과 회귀 테스트`
- `fix: 2호선 빠른하차 하행을 혼잡도 내선에 맞춤`
- `docs: ADR 0001을 정제 데이터 기준으로 고침`

배치 워크플로의 데이터 커밋은 `chore:` 타입이고, 메시지에 원본별 기준 기간을 적습니다(#11).

## Pull Request

- 이슈 하나 = PR 하나를 기본으로 합니다. 본문에 `Closes #번호`를 적어 이슈와 잇습니다.
- 병합 전에 `AGENTS.md` "검증 흐름"을 통과합니다.
